# Руководство разработчика

[English](../en/development.md) | [Инструкция пользователя](user-guide.md)

## Что установить

Для сборки и тестов нужны Windows, Python 3.11 или новее и Git. Проверенная NVDA использует 32-разрядный Python 3.11, поэтому код дополнения должен работать с этой версией. Среда разработки использовала Python 3.14.7. wxPython и модули NVDA уже входят в NVDA; устанавливать отдельный wxPython в неё не нужно.

В `requirements-dev.txt` закреплены четыре пакета: ConfigObj читает манифест, Markdown готовит документацию, pytest запускает тесты, Ruff проверяет код. Для проверки работающего интерфейса нужны NVDA и PowerManagerII. Модульные тесты и сборка обходятся без них. GitHub CLI нужен только для публикации из командной строки.

## Подготовка и сборка

В корне репозитория откройте PowerShell и выполните:

```powershell
.\tools\bootstrap.ps1
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check addon tests tools/build.py tools/check_docs.py
.\.venv\Scripts\python.exe tools/check_docs.py
.\.venv\Scripts\python.exe tools/build.py
```

Если PowerShell блокирует запуск сценариев, создайте среду командой `python -m venv .venv`. Затем выполните `.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt`. Менять политику выполнения PowerShell не требуется.

В папке `dist` появятся установочный файл `.nvda-addon`, ZIP с исходниками и `SHA256SUMS.txt`. Дополнение содержит Python-код, карту элементов, лицензию и встроенную документацию на двух языках. Пользователю достаточно установочного файла.

Порядок файлов и время внутри ZIP фиксированы. При одинаковых исходниках и среде сборки архивы совпадают. Сборщик проверяет синтаксис Python 3.11, поля манифеста, состав и целостность архива. Запуск `.\.venv\Scripts\python.exe -O tools/build.py` в той же среде проверяет сборку при отключённых операторах assert.

## Устройство проекта

| Файл | Назначение |
| --- | --- |
| `addon/appModules/powermanager/__init__.py` | События и команды NVDA, доступные свойства элементов, проверки действий |
| `native.py` | Поиск окон и обмен ограниченными по времени сообщениями Windows |
| `model.py`, `views.py`, `reports.py` | Состояние ИБП, показания и текст истории |
| `labels.py`, `dialog_map.json` | Названия элементов, признаки диалогов и порядок переходов |
| `manual_tabs.py`, `view_dialog.py`, `dialogs.py` | Окна чтения и ручное открытие вкладок |
| `help.py` | Контекстная помощь дополнения |
| `addon/appModules/appinfo.py` | Отдельное окно сохранённых файлов Richcomm |
| `docs/en`, `docs/ru` | Исходники документации |
| `tests` | Модульные тесты с заменами объектов NVDA и элементов программы |

Файлы без полного пути лежат в `addon/appModules/powermanager`. Дополнение читает окна распознанного процесса PowerManagerII. Прямого обмена с оборудованием ИБП и записи в настройки производителя в коде нет.

## Изменение навигации

Фокус на заголовке и открытая вкладка должны быть разными состояниями. Стрелки и Control+Tab перемещают фокус. Enter и пробел открывают вкладку. Tab ведёт к данным открытой страницы, даже если перед этим фокус стоял на другом заголовке.

Отложенный переход должен учитывать новый ввод, активное окно и настоящий фокус Windows. Не подменяйте фокус NVDA предположением, если Windows не выполнила переход. Вкладки используют `TCS_BUTTONS` и `TCM_SETCURFOCUS`, чтобы Windows различала фокус и выбор.

Перед подписью и активацией элемента проверяйте признаки диалога. Сохраняйте ограничения времени и объёма чтения таблиц. Скрытые старые значения нельзя выдавать за свежие; числовые показания доступны только при подтверждённой связи.

Команды питания, самотестирования, расписания и удаления должны проходить подтверждение с повторной проверкой параметров. Успешную отправку команды проверяйте на заменах объектов в тестах, без реального ИБП.

## Проверка изменений

Сначала запустите модульные тесты и проверку кода. Соберите дополнение и по возможности установите его в отдельный профиль NVDA. Журнал NVDA поможет найти исключения, но перед передачей удалите из него личные данные.

[План ручной проверки](testing.md) описывает работу с настоящими клавишами. Сверяйте элемент, который произносит NVDA, с фокусом Windows. Обход объектов программы в коде ещё не доказывает, что клавиши работают.

Локальные инструменты исследования и исходные журналы первой машины исключены из репозитория. Здесь есть модульные тесты и план проверки для другой установки. Файлы производителя, личные настройки, получатели оповещений и диагностические модули не должны попадать в выпуск.

## Документация и переводы

Правьте Markdown в `docs/en` и `docs/ru`, затем запускайте сборку. Она создаёт HTML в `addon/doc/en` и `addon/doc/ru`; вручную эти файлы править не нужно. В обеих инструкциях должны совпадать клавиши, действия и ограничения.

В версии 1.0.0 интерфейс и контекстная помощь русские. Английская документация не меняет язык интерфейса. Для будущего перевода потребуются механизм переводов дополнений NVDA и проверка каждого языка PowerManagerII.

## Выпуск версии

1. Укажите номер в `addon/manifest.ini`, обновите примечания к выпуску, историю изменений и имена загрузок в документации.
2. Выполните проверки и сборку. Убедитесь, что в архиве исходников нет личных файлов.
3. Зафиксируйте проверенные файлы в Git. Автоматическая проверка GitHub запускает тесты в Windows с Python 3.11 и 3.14 и сохраняет сборку.
4. Запустите `tools/publish.ps1`. Он создаст публичный репозиторий при необходимости, отправит коммит, дождётся проверок, поставит тег и опубликует три файла выпуска. Для этого нужны авторизованный GitHub CLI и рабочая папка без незакоммиченных изменений.

Номер уже опубликованного выпуска уменьшать нельзя. С 1.0.0 начинается публичная история; прежние номера использовались в локальных сборках.
